## Overview

A restrained registry operations panel for network operators. User explicitly
rejected the colourful presentation and requested shadcn/ui, less explanatory
clutter and English. Resources, hierarchy and actionable findings own the main
workspace. Rules, source evidence and resource details use secondary sheets.
No promotional hero, decorative charts, repeated explanations or green badges
on every healthy row. No Japan-market scope is implied by the timezone.

Runtime token ownership is Model B: frontend/src/index.css owns the official
shadcn neutral semantic variables (--background, --foreground, --primary,
--muted-foreground, --border, --destructive) mapped to Tailwind via @theme inline.
This file mirrors design intent. shadcn/ui Radix Nova components in
frontend/src/components/ui own controls; App.tsx owns composition and data flow.

## Colors

White surfaces, near-black text and actions, light grey sidebar, subtle borders.
Amber labels and a pale yellow row mark ASNs without current announcements
when activity was seen within three calendar months, or when the ASN is new.
This is informational and does not increase the finding count. Red is limited
to errors and finding indicators, always accompanied by text or a
count. Healthy states use plain text. Global scrollbar tokens also live in
index.css. Light mode is the shipped mode; forced colours follow the platform.

## Typography

Geist Variable is bundled locally through fontsource, with a sans-serif fallback.
Monospace is reserved for prefixes, ASN and ORG handles. English UI uses en-GB
number/date formatting and explicit UTC. Registry names remain original source
content. Cached findings render message_en without requiring a fresh analysis.

## Layout

216px neutral sidebar owns the audit heading, description, LIR identity, source
timestamp, cache expiry and compact resource counts. The main area owns the regID
form before analysis, and filters, table and pagination after completion.
Sidebar view navigation appears only once results are ready. Another analysis
replaces the completed scan form and resets to a focused empty regID input.
No recent analyses list or public-data badge. The sidebar footer links the
current-year copyright to edwardcode.net. Cache text shows an exact expiry
after completion. Resource counts use compact sidebar rows. The main workspace
uses filters and a server-paginated table. Page sizes 25/50/100. Tree branches
load bounded child pages on expansion. Resource details use a modal Sheet.
At narrow widths sidebar becomes horizontal navigation and filters wrap.
Tables own horizontal overflow; the document remains naturally scrollable.
The desktop sidebar stays at the viewport top with its own overflow if needed;
mobile navigation stays in normal document flow.
Initial state has no fabricated results. URL owns job, filters and page.

## Elevation & Depth

Borders separate persistent content. Only transient shadcn popovers/sheets use
their built-in elevation and scrim. No gradients, glass, neon or large shadows.

## Shapes

Use shadcn neutral rounded controls and 8px workspace borders. Dense table rows
retain readable spacing and keyboard focus. Lucide utility icons have labels.

## Components

Real shadcn/ui components generated by its CLI: Button, Input, Label, Badge,
Alert, Progress, Table, Select, DropdownMenu and Sheet. Radix owns authored select
popup keyboard behaviour and modal focus trapping. Sheet close restores trigger
focus, Escape closes, background is inert. Shared API errors use persistent
Alerts. Forms use noValidate and inline errors. Search is 300ms debounced,
IME-aware, abortable, with explicit clear and focus restoration.

Progress reports current stage and actual counts. Unknown totals are
indeterminate; no invented overall completion percentage. Reduced motion removes
nonessential animation. Public scope and partial coverage remain explicit.

## Do's and Don'ts

- Keep technical codes and provenance in resource details.
- Label historical snapshots and incomplete coverage.
- Distinguish RIPE policy, schema, audit rules and manual checks.
- Never turn missing source data into a clean result.
- Never represent a BGP-only row as a RIPE registration.
